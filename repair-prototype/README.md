# 拾帧 · 本地视频修复工具 v0.2

Windows 桌面工具，Python 3.11+ 与 Tkinter 界面。视频、参考片与 AI 推理在本机处理，不上传素材。

## 启动

已经安装全部引擎时，双击 `启动视频修复工具.bat` 即可。首次克隆仓库请先运行两个安装脚本；仓库不包含引擎二进制与模型。旧窗口仍在运行时，重新打开的是新版窗口。

在其他电脑上，安装含 Tkinter 的 Python 3.11+，让 `python` / `pythonw` 可用，然后复制整个项目目录；包括 `.tools` 时无需再次下载。

1. 缺少基础引擎时运行 `安装视频引擎.bat`。
2. 缺少 AI / 索引引擎时运行 `安装扩展引擎.bat`。
3. 双击 `启动视频修复工具.bat`，选择原视频与健康磁盘上的输出目录。

首次安装需要联网，后续处理不需要联网；每台电脑会重新检测实际 GPU。

也可以在本目录运行 `python app.py`。运行依赖仅下载到本项目 `.tools/`，不修改 PATH。安装脚本从 FFmpeg 官方下载页列出的 Gyan Windows 构建下载并验证 SHA256：https://ffmpeg.org/download.html 。

## 功能

- **文件修复**：自动优先重新封装；失败或输出解码错误时尝试 H.264/AAC 重新编码抢救。也可手动选择单一策略。
- **画质修复**：传统降噪、锐化、提亮、去隔行与 Lanczos 放大；可选 Real-ESRGAN 真实 AI 超分辨率，支持实拍 / 动画模型、2 倍 / 4 倍输出。
- **索引重建**：接入 Untrunc，以同设备、同录制设置的健康参考片重建 MP4/MOV 索引；重建后继续封装 / 转码与完整验证。
- **预览**：生成并验证开头最多 5 秒的画质处理结果；通过“播放原片”和“播放结果”打开播放器比较。预览在临时目录，关闭应用时清理；满意后执行完整处理。
- **视频诊断**：MP4/MOV 顶层容器结构、轨道与时长信息、完整视频和音频解码检查。
- **导出验证**：输出必须包含视频轨道，解码出实际帧，且完整解码没有错误才另存 MP4。报告记录时长、轨道、解码帧数、错误与处理命令。日志较大时记录最后 64 KiB 与总字节数。
- **取消任务**：中止子进程并清理工作副本；原文件始终只读。复制出现读取错误时记录失败块起始字节偏移并停止，不用零填充掩盖损坏。

输出使用唯一名称，不覆盖原片或既有文件。每次完整任务在输出目录生成同名 JSON 报告；失败与取消也保留报告。报告包含本机路径，分享前可自行脱敏。

## AI 超分辨率使用

进入“画质修复”，勾选“启用 AI 超分辨率”，选择实拍通用 / 动画和 2 倍 / 4 倍。建议先生成短预览，确认效果和速度后处理完整视频。勾选 AI 后，传统“输出尺寸”禁用，以 AI 倍率为准。

实拍通用使用 `realesrgan-x4plus`，以 4 倍推理，选择 2 倍时再缩小；动画使用对应倍率的 `realesr-animevideov3`。降噪、提亮和去隔行在推理前应用，锐化在推理后应用。

**显卡自适应**：程序使用 Vulkan API 枚举实际设备与编号，不按型号名称绑定逻辑。自动模式优先独立显卡，同类设备再比较本地内存堆大小；也可手动选择检测到的 GPU。分块默认由引擎按显存预算决定。Intel、NVIDIA、AMD 的具体可用性取决于驱动的 Vulkan 支持，换电脑后使用“检测”刷新即可。推理失败时可尝试 64 / 32 的较小分块。没有可用 Vulkan GPU 时会明确报错，不把插值冒充 AI 结果；当前不支持 CPU 推理。

管线最多以 6 帧一批读写，处理后合成并清理图片；临时帧空间随分辨率和倍率增加，不随视频总时长无限增长。原片音轨随后合并，音轨较短时仍保留全部已处理帧。

AI 输出是按源时间戳采样得到的平均帧率对应的**恒定帧率**；可变帧率素材会重采样。手机的 90 度整数倍旋转会规范化到画面。当前使用 8 位 RGB / H.264 输出，未实现 HDR 保真、时序 AI 或专门的人脸重建；逐帧处理可能有纹理闪烁，效果需观看确认。

## 缺失索引重建使用

在“文件修复”选择损坏 MP4 / MOV，再选择“健康参考片”，必须尽量来自同一设备、相同分辨率、帧率和编码设置。策略选“参考视频重建索引”即可；自动策略在视频轨道无法识别且已提供参考片时也会尝试重建。

工具建立损坏文件与参考片的工作副本，先完整解码检查参考片，再在工作目录调用 Untrunc。重建后重新封装，必要时转码，最终必须通过完整解码检查才另存。原片和参考片始终只读。

“跳过无法识别的损坏数据”适用于局部损坏，但可能跳过无法恢复的内容。参考片时长不代表损坏片原始时长；原片时长未知时不计算恢复比例。索引重建不能还原已经丢失的数据，设备或设置不匹配也可能失败；请核对结果内容、时长和音画同步。

报告追加实际 GPU、模型、分块、AI 处理帧数、引擎安装来源、参考片检查与重建结果。磁盘无法写入报告时会在界面提示保存失败。

## 当前范围

- 普通重新封装/转码需要引擎仍能识别视频轨道；缺失 `moov` 索引时需要健康参考片与 Untrunc 重建。
- 严重截断、加密文件、完全丢失的数据不能保证恢复。解码通过表示输出可完整解码，不代表恢复了缺失画面或画面无瑕疵。
- 以首条视频轨道作为编码目标，保留可处理的所有音轨；字幕、章节和额外数据轨道暂不导出。多视频轨道重新编码可能减少轨道，报告会标注。
- 恢复时长与输入可识别时长相比减少超过 2%，或者视频/音频轨道减少，标记为“部分恢复”。输入时长未知时不计算比例；比例仅衡量时长，不是内容恢复百分比。
- 不支持任务队列、独立安装包与硬盘坏道恢复。硬件读取故障应先获取稳定副本。
- 磁盘空间预检查只给出最低估计；放大视频可能需要更多空间，空间不足会报告失败。

## 验证

运行 `python -m unittest discover -s tests -v`。测试会生成 H.264/AAC 健康样本，以及截断、丢失索引、媒体数据破坏等模拟样本，检查导出验证、原片不变、取消和读取失败。

运行 `python tests/ui_smoke.py` 验证实际桌面事件循环与后台任务联动，包含 AI 预览与索引重建。验证结果见 `VALIDATION.md`。扩展引擎缺失时集成测试明确失败，避免静默跳过。

模拟损坏测试不能证明真实损坏视频一定可恢复；还需要用实际素材验证效果。

目前在本机 Iris Xe 验证真实推理，其他显卡的自动 / 手动选择由逻辑测试覆盖，仍需在对应硬件上实测。真实素材由用户后续验证：建议记录损坏来源、拍摄设备与设置、参考片来源和处理策略，保留 JSON 报告；观看开头、中间、结尾并核对同步。

滤镜与处理参数参考：https://ffmpeg.org/ffmpeg.html 、https://ffmpeg.org/ffmpeg-filters.html 。

扩展引擎来自作者发布包：<https://github.com/xinntao/Real-ESRGAN-ncnn-vulkan>、<https://github.com/anthwlock/untrunc>。Real-ESRGAN 固定 `v0.2.5.0 / 20220424`，旧资产没有作者提供的 SHA256，项目从官方 HTTPS 下载后记录摘要并在后续安装按固定摘要校验；这不是额外的作者签名。Untrunc 按 GitHub 发布资产 SHA256 校验，记录构建信息。随包许可文件保留在 `.tools` 子目录。Untrunc 自带的视频库与基础 FFmpeg 使用独立进程，互不替换。
